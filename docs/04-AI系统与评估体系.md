# 04 · AI 系统与评估体系

> 承接报告 §5.1/§5.3（AI 原则与六引擎）、§6.4（AI 层架构）。核心立场：**AI 的护城河不在模型，在评估与迭代闭环**。本文定义六引擎的工程规格、工具调用协议、模型路由、提示词版本管理与黄金评估集运作机制。

---

## 1. AI 原则 → 工程约束

报告 §5.1 四原则逐条落地为可检验的工程机制：

| 原则 | 工程约束 | 验证方式 |
| --- | --- | --- |
| 建议不擅断 | 所有写操作经"草案协议"：AI 返回 `draft=true` 的操作对象，客户端渲染确认 UI，用户确认才进写入管道；高频接受可渐进授权（`ai_memory.kind=grant` 记录，每类操作单独授权，可随时撤销） | 代码评审检查项：AI 路径不得直接调用写仓库 |
| 可解释 | 每条建议必带 `reason` 字段（模型生成 + 关键证据引用），UI 强制展示；缺失 reason 的建议在网关层丢弃 | 评估集包含 reason 质量评分 |
| 可整体关闭 | `AI 总开关` 为一级设置：关闭后网关 SDK 拒绝出网，六引擎全部退化为手动路径；关闭态功能完整性在 E2E 冒烟集中有专门用例 | E2E：no-ai 模式全功能走查 |
| 最小化取数 | 网关强制数据分级（§5.3）：L1 默认可发、L2 需授权、L3 仅 BYOK/本地；越级请求在网关直接拒绝并告警 | 网关单测覆盖分级矩阵 |

## 2. 六引擎工程规格

> 验收标准沿用报告 §5.3；补充模型档位、延迟预算与评估集规模。模型档位：`端上`（规则/系统模型）、`轻`（低成本云模型）、`旗舰`（最强云模型）——实际型号由网关配置表动态指定（§5.1）。

| # | 引擎 | 阶段 | 输入 | 输出（结构化） | 档位 | 延迟预算 | 验收 | 评估集 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 智能捕获 | Capture | 原始输入串 | `{title, due?, reminder?, estimate?, energy?, tags?, project_hint?}` | 端上→轻回落 | 端上 <300ms | 常用表达解析准确率 ≥95% | parse ≥300 条 |
| 2 | 澄清副驾 | Clarify | 收件箱条目（L1/L2） | `{verdict: 垃圾/参考/行动/ someday/等待, target_project?, reason, draft_ops[]}` | 轻 | <3s/条 | 建议采纳率 ≥70%；处理速度 3× 手工 | clarify ≥80 条 |
| 3 | 项目拆解师 | Organize | 项目名+备注（L1/L2） | `{steps:[{title, why, order, estimate?}], followup_questions[]}` | 旗舰 | <10s | "可直接使用不需大改" ≥60%（G1 门 ≥50%） | decompose ≥60 条 |
| 4 | 今日规划师 | Engage | 当日任务集+日历空闲+精力曲线+历史用时（L1） | `{blocks:[{task_id, start, end, why}], now_focus}` | 轻（重排本地算） | <5s | 采纳规划 ≥3 天/周（周活口径） | plan ≥40 条 |
| 5 | 回顾记者 | Reflect | 周数据快照（L1 统计） | `{summary, highlights[], stalled_projects[], next_week[], followup_seed[]}` | 旗舰 | <20s | 周回顾打开率 ≥40% | review ≥40 条 |
| 6 | 任务库对话 | 全部 | 自然语言问句 | `{intent, query_ast}`（读）`{draft_ops[]}`（写） | 旗舰 | <5s | 意图准确率 ≥90%；写操作 100% 走确认流 | query ≥80 条 |

**共同底座**：统一 JSON Schema 输出（`packages/protocol/ai/`）+ 函数调用工具集（§3）+ 黄金评估集回归（§6）。解析类输出全部走 schema 约束解码，禁止自由文本正则反解。

## 3. 工具调用协议（写操作草案制）

工具集是六引擎与 MCP Server（Phase 3）共用的能力面。v1 清单：

```jsonc
// 工具定义（节选，完整见 packages/protocol/ai/tools.json）
{ "name": "create_task",   "draft_default": true,
  "params": { "title":"str", "due_date?":"date", "project_hint?":"str", … } }
{ "name": "update_task",   "draft_default": true, "params": { "id":"uuid", "patch":"object" } }
{ "name": "reschedule",    "draft_default": true, "params": { "task_ids":"uuid[]", "to_date":"date", "why":"str" } }
{ "name": "decompose_project", "draft_default": false,   // 生成建议本身不是写操作
  "params": { "project_id":"uuid", "depth?":"int" } }
{ "name": "search_tasks",  "draft_default": false, "params": { "query_ast":"ast" } }
{ "name": "summarize_period", "draft_default": false, "params": { "range":"period" } }
```

草案流程：`模型调用工具 → 网关校验 schema/分级/额度 → 返回 draft → 客户端确认 UI（展示 diff + reason）→ 用户确认 → 走正常写入管道（产生 oplog）`。**渐进授权**后 draft_default 可对该用户该工具翻转为自动执行，但保留操作日志与一键撤销（24h 内）。

## 4. 端上解析子系统（引擎 1）

优先级链（ADR-006）：

1. **规则引擎**（`packages/nlp`）：日期短语库（中/英）、时长表达式（`30min/半小时`）、精力标记（`!高`）、标签（`#`）、项目路由（`@项目`）——覆盖高频结构化表达，零成本零延迟。
2. **系统检测器**：Apple 平台 DataDetectors（日期/地址）+ Foundation Models 框架（iOS/macOS 26+）做轻量意图解析；不可用时静默跳过。
3. **云回落**：端上置信度 < 阈值且用户已开启云端 AI → 发 L1 字段到网关轻档解析；未开启则保留纯文本入收件箱（永不丢数据）。

- 置信度信号：规则命中数、字段冲突（两个日期）、解析失败残留标记——落 `capture_used.parsed_ok` 遥测。
- 评估：parse 评估集按"规则引擎可解 / 需系统模型 / 需云端"分层标注，回归时分层报准确率，防止规则集退化。

## 5. 模型路由网关

### 5.1 路由表（配置化，非硬编码）

```yaml
# server: ai_gateway/routing.yaml（版本化）
default_policy: cheapest_capable
routes:
  - engine: capture_fallback   tier: light    timeout_s: 5
  - engine: clarify            tier: light    timeout_s: 8
  - engine: decompose          tier: frontier timeout_s: 30
  - engine: planner            tier: light    timeout_s: 10
  - engine: review             tier: frontier timeout_s: 40
  - engine: conversation       tier: frontier timeout_s: 15
fallback: { frontier: light }   # 旗舰超时/限流时降级，标记 degraded 建议
```

### 5.2 网关职责

1. **鉴权与额度**：订阅档位 → 月度调用额度（§8）；BYOK 请求绕过额度走用户自己的 key（服务端只做 schema/分级校验，密文传参不解密）。
2. **数据分级强制**（§1）：请求体带字段分级标注，L2/L3 越级直接 403。
3. **脱敏**：L1 白名单字段之外的内容默认替换为占位符（`[笔记正文已省略]`）。
4. **缓存**：同项目上下文的拆解请求按 `(project_hash, prompt_version)` 缓存 24h。
5. **成本账本**：逐请求记录 token 用量与模型单价，聚合到用户/引擎维度（01 文档 §6 风险 6 的数据源）。
6. **提示词版本**：请求头带 `prompt_version`，网关按版本拉取提示词（§7），评估与线上行为可对应。

## 6. 黄金评估集（核心工程资产）

### 6.1 构建规范

- **来源**：Phase 0 访谈与候补名单用户提供的真实表述，脱敏后入库；每季度补充一次私测/公测埋点中的失败样例。
- **规模**（Gate 要求）：parse ≥300（Phase 0 200 → S09 300）、clarify ≥80、decompose ≥60、plan ≥40、review ≥40、query ≥80；含 ≥15% 对抗样例（歧义、错别字、方言表达）。
- **格式**：`tools/golden/<engine>/<case-id>.yaml`，含 `input`、`expect`（字段级期望或 rubric）、`difficulty`、`tags`（分层统计用）。
- **纪律**：评估集变更走 PR 评审；线上发现的 bad case 先进评估集再修提示词（防止"按例修例"过拟合）。

### 6.2 评估 harness（`tools/eval`，Phase 0 建成后长期使用）

```bash
dart run tools/eval run --engine parse --mode replay   # 回放录制响应，零成本，进 CI
dart run tools/eval run --engine parse --mode live     # 真跑，每夜/发版前
dart run tools/eval report --baseline v12              # 与基线对比，输出红绿报告
```

- **record/replay**：live 运行时录制模型响应入库；PR 的 CI 用 replay 保证零 API 成本与确定性；prompt/模型/路由变更的 PR 必须附 live 报告。
- **指标**：解析/查询类用字段精确匹配+类型校验；生成类（拆解/回顾）用 rubric 化 LLM 评审（1–5 分，≥4 为"可直接使用"）+ 人工抽检 10%。
- **门槛**（CI 阻塞）：见 §2 表验收列；任何引擎低于门槛，相关发布回滚提示词版本。

### 6.3 发布流程（提示词/路由变更）

```text
改提示词或路由 → 本地 replay 快速自检 → live 评估报告（≥门槛且不劣于基线 -1pp）
→ ADR 式 PR 评审 → 灰度 10% 设备（网关按 device 分流）→ 72h 采纳率无回退 → 全量
```

## 7. 提示词与配置版本管理

- 目录：`server_packages/ai_gateway/prompts/<engine>/v<major>.<minor>.md` + `meta.yaml`（适用模型、输出 schema 版本、变更说明）。
- 语义化版本：minor = 措辞优化（replay 无差异）；major = 行为变更（必须 live 报告）。
- 线上问题回滚 = 路由表指回旧版本，秒级生效。

## 8. 额度与成本

| 档位 | 月度云端 AI 额度 | 说明 |
| --- | --- | --- |
| Free | 约 30 次云端调用（报告 §9） | 端上解析不计额 |

- 成本预算：重度用户云端成本 $0.5–2/月（报告 §6.4）；月度经营看板跟踪"单付费用户 AI 成本"，触发线见 01 文档 §6 风险 6。
- 降本杠杆优先级：端上命中↑ → 缓存命中↑ → 轻档占比↑ → 旗舰仅拆解/回顾。

## 9. 遥测与采纳率度量

- 采纳率归因链：`ai_suggestion_shown → (accepted | rejected | timeout)`，以 rejected 的可选理由（free text，用户主动填写）作为评估集补充来源。
- A/B 框架：网关按设备 ID 分流（提示词/模型/默认参数），客户端无感；最小样本量由指标方差预估，运行期 ≥2 周。
- 反作弊/隐私：遥测只含计数与枚举（01 文档 §7.1），正文与标题永不外发；A/B 元数据不落 AI 供应商侧。
