# 02 · 工程架构与规范

> 承接报告 §6（技术方案与架构）。本文确定仓库结构、技术选型（含 ADR 决策记录）、编码/测试/CI-CD 规范。

---

## 1. Monorepo 结构

单仓库管理客户端、服务端与共享包。Phase 0 原型阶段（W1）即按此结构初始化，避免原型代码二次迁移。

```text
agendum/
├── apps/
│   ├── client/               # Flutter 应用（iOS/macOS/Android/Windows/Web 条件编译）
│   │   ├── lib/
│   │   │   ├── app/          # 入口、路由、主题、DI 装配
│   │   │   ├── features/     # 按功能域分包：capture/ inbox/ today/ projects/ review/ settings/ ...
│   │   │   └── platform/     # 平台桥：menu_bar/ shortcuts/ eventkit/ share/ widgets/
│   │   ├── ios/  macos/  android/  windows/  web/
│   ├── server/               # Dart Frog 服务（同步/账号/AI 网关代理/计费回调）
│   └── web/                  # Phase 3：Web 端（复用 client 域代码，轻壳）
├── packages/
│   ├── domain/               # GTD 规则引擎（纯 Dart，零依赖 UI/DB，可单测）
│   ├── db/                   # Drift schema、DAO、迁移、FTS5 索引
│   ├── sync/                 # 同步客户端引擎（oplog、LWW 合并、加密挂接）
│   ├── protocol/             # 客户端/服务端共享：API 契约、oplog 消息、工具调用 schema
│   ├── nlp/                  # 端上解析：规则引擎 + 平台检测器适配层
│   ├── ai_client/            # AI 网关客户端 SDK（BYOK、额度、草案-确认协议）
│   └── ui/                   # 设计系统：tokens、组件库、动效曲线、空状态
├── tools/
│   ├── eval/                 # 黄金评估集 harness（Phase 0 产出，持续使用）
│   ├── golden/               # 评估集数据（YAML/JSONL，脱敏）
│   └── seed/                 # 开发种子数据（10k 任务压测库生成器）
├── server_packages/          # 服务端专用模块（仅 apps/server 引用）
├── docs/                     # 本文档库 + ADR
├── .github/workflows/        # CI/CD
└── makefile                  # 任务编排（pub workspaces 原生工作区，ADR-015）
```

**依赖规则**（自定义 lint + CI 强制）：

- `domain` 不依赖任何 Flutter/DB 包；`db`/`sync` 依赖 `domain`；`apps/*` 依赖全部 packages；`packages/*` 之间禁止循环依赖。
- 平台桥代码（`platform/`）只能被 `features/` 通过接口调用，接口定义在 `domain` 或 `ui`。

## 2. 技术栈清单

> 版本策略：Flutter/Dart 锁定于 `mise.toml`，升级走独立 PR + 全量回归；依赖在各包 `pubspec.yaml` 声明、由 pub workspaces 统一解析（根 `pubspec.lock` 入库保证可复现）。

| 层 | 选型 | 理由 | 备选（放弃原因） |
| --- | --- | --- | --- |
| 跨端框架 | Flutter stable（kickoff 时锁定） | 报告 §6.2 主方案；自绘引擎保证跨端一致 | RN（质感上限）、双端原生（团队规模） |
| 状态管理 | Riverpod 3 | 编译期安全、与 Drift Stream 天然配合、测试友好 | Bloc（样板多）、Provider（弱类型） |
| 本地存储 | SQLite + Drift | 类型安全、响应式流、FTS5 全文、迁移管理成熟 | Isar（同步场景生态弱） |
| 服务端 | Dart Frog + package:postgres + Postgres 16 | 与客户端共享 `protocol`/领域代码，1 人后端产能最大化 | Go/TS（跨语言协议维护成本） |
| 服务端部署 | Docker Compose on VPS（Hetzner/国内云）+ Cloudflare | 1.0 前成本最优；可观测齐全后评估 K8s | Serverless（同步长连接不友好） |
| 模型/迁移 | Drift migrate + 服务端 dbmate | 双端迁移各自可回滚 | — |
| 加密 | `cryptography` + `sodium_libs`：Argon2id 派生、XChaCha20-Poly1305；BIP39 恢复短语 | 报告 §6.3 E2EE 要求 | AES-GCM（无显著优势） |
| 日历 | Apple：EventKit（平台桥）；非 Apple：googleapis（Calendar API v3）；CalDAV 后置 | EventKit 与系统日历双向最稳 | 纯 CalDAV（Apple 上绕远路） |
| 计费 | RevenueCat（App Store / Play / Stripe 统一） | 小团队不重造订阅账务；entitlement 跨端一致 | 自建（账务边缘 case 太多） |
| 崩溃/观测 | Sentry（Flutter+Server） | 崩溃率 <0.1% 闸门的数据源 | Firebase（隐私画像不符） |
| 产品分析 | PostHog（可自托管） | 事件白名单制、可自托管符合隐私叙事 | Amplitude（数据出境顾虑） |
| 推送 | APNs / FCM（Phase 2 同步提醒） | 系统能力 | — |
| MCP | 官方 Dart MCP SDK | 与 AI 工具层同语言复用 | TS SDK（跨语言） |
| 搜索 | SQLite FTS5（unicode61 + 自定义 zh tokenizer） | 本地优先、零服务 | Meilisearch（需常驻服务） |

## 3. 架构决策记录（ADR）

> 格式：ID ｜ 决策 ｜ 关键理由 ｜ 触发重审的条件。完整 ADR 落盘于 `docs/adr/`（每个 ADR 一个文件，本文为索引）。

| ID | 决策 | 关键理由 | 重审条件 |
| --- | --- | --- | --- |
| ADR-001 | 客户端框架 = Flutter | 报告 §6.2；3 人客户端组覆盖五端 | 质感走查连续 3 次不可达红线 |
| ADR-002 | 状态管理 = Riverpod 3 + Drift Stream 响应式 | UI 即数据库投影，减少中间状态同步 bug | — |
| ADR-003 | 后端语言 = Dart（Dart Frog） | oplog 协议、领域模型、加密序列化与客户端共享一份代码；1 人后端的关键杠杆 | 同步 QPS 或运维生态瓶颈 |
| ADR-004 | 同步 = 自研 oplog 字段级 LWW + 墓碑 + 分数索引排序 | 报告 §6.3；实体关系简单无实时协作 | S08 混沌套件不全绿 → 切 PowerSync 评估（01 文档 §6 风险 1） |
| ADR-005 | E2EE = Argon2id(passphrase) → 主密钥；XChaCha20-Poly1305 行加密；BIP39 恢复短语 | 服务端零明文（报告 §5.5）；密码找回走恢复短语，不做服务端重置 | 恢复流程可用性测试失败率 >5% |
| ADR-006 | 端上解析 = 规则引擎优先 + Apple DataDetectors/Foundation Models 框架 + 云回落 | 免费、离线、隐私；报告 §6.4 端云分工 | 非 Apple 平台解析准确率缺口 >10pp |
| ADR-007 | 计费 = RevenueCat | 订阅账务/收据校验跨端统一，Phase 2 工期从 6 周压到 2 周 | Web 端计费（Phase 3 后期，Stripe 直连） |
| ADR-008 | 日历 = EventKit（Apple）优先、Google API（非 Apple）次之 | EventKit 免 OAuth 流程且用户体感即系统日历 | Outlook 需求显著（Phase 3 评估） |
| ADR-009 | 观测 = Sentry + PostHog（事件白名单 + 可自托管） | 隐私公理要求遥测可审计、可解释 | — |
| ADR-010 | MCP = 官方 Dart SDK，复用 AI 工具层 | 报告 §6.5"复用 AI 层工具集，成本不高" | SDK 成熟度不足（备选 TS，协议层已隔离） |
| ADR-011 | 主键 = UUIDv7（时间有序） | 分布式生成 + B-tree 插入友好 | — |
| ADR-012 | 重复规则 = RFC 5545 RRULE 受控子集（DAILY/WEEKLY/MONTHLY/BYDAY/INTERVAL/COUNT/UNTIL） | 覆盖 95% GTD 场景，避免全量 iCalendar 复杂度 | 用户调研出现高频复杂规则诉求 |
| ADR-013 | 账号 = 邮箱 + 主密码派生密钥，无第三方登录 | 第三方 OAuth 与 E2EE 密钥派生冲突；恢复短语兜底 | 转化漏斗数据证明注册流失主因 |
| ADR-014 | 手动排序 = 分数索引（fractional indexing，Figma 式） | 拖拽排序只改单字段，天然兼容字段级 LWW | 索引退化（长度超限）→ 重排压缩 |
| ADR-015 | 构建编排 = Dart pub workspaces（根 pubspec `workspace:`），弃用 melos | Dart 3.6+ 原生支持单次解析；少一个全局工具依赖，IDE 与 CI 解析天然一致（W1 实施时确定） | 包数 >12 或需要按包脚本编排时评估 melos |

## 4. 客户端架构规范

### 4.1 分层

```text
UI (features/*)  →  应用状态 (Riverpod Notifier)  →  领域服务 (domain)  →  仓库 (db+sync)  →  SQLite
        ↑___________________ Drift Stream 响应式回流 _____________________|
```

- **UI 不写业务**：视图只消费 provider 与发出意图（intent）；GT 的状态流转（inbox→next→done…）只存在于 `domain`。
- **数据库是唯一事实源**：不引入内存态缓存层；视图 = 对表的自定义查询投影（透视图/今日视图即查询，见报告 §5.4"透视可保存查询"）。
- **离线全功能**：任何写路径不得前置网络调用；同步失败静默重试，UI 无感知。

### 4.2 模型与序列化

- 领域模型用 Freezed 不可变对象；DB 行 ↔ 领域模型 ↔ 协议 JSON 三向映射集中在 `db/mappers` 与 `protocol`，禁止散落。
- 日期统一存 epoch days（日期）/ epoch seconds（时刻）；时区规则：日历时间块按事件时区，任务 due 按用户本地日（存 date 不存 datetime，含时区偏移列，处理跨时区飞行场景）。

### 4.3 主题与设计 tokens

- `ui/tokens` 定义颜色/字号/间距/动效曲线（统一 curves 清单），亮暗双主题从同一 token 派生；禁止裸写 `Color(0x…)`。
- 毛玻璃、菜单栏悬浮窗等 macOS 质感集中在 `platform/` 实现，UI 层不感知实现。

## 5. 服务端架构规范

- 模块：`/auth`（邮箱+密码、设备注册、密钥登记）、`/sync`（push/pull，见 03 文档 §4）、`/ai`（网关代理：脱敏、配额、模型路由，见 04 文档 §5）、`/billing`（RevenueCat webhook）、`/admin`（内部看板）。
- Postgres 表与客户端 DDL 同构（实体表 + oplog 服务端侧表）；迁移用 dbmate，向前兼容滚动发布。
- 备份：每日全量 + WAL 归档到对象存储（R2），保留 30 天；恢复演练每季度一次（01 文档 §6 风险 5 兜底）。
- 无状态服务可水平扩展；oplog 全局序号由 Postgres sequence 保证，多实例安全。

## 6. 编码与协作规范

| 项 | 规范 |
| --- | --- |
| 语言/Lint | Dart analyzer strict + 自定义 lint（禁循环依赖、禁裸色值、禁 UI 层直查 SQL） |
| 提交 | Conventional Commits（feat/fix/chore/docs/refactor/test/perf），PR 标题即提交语义 |
| 分支 | trunk-based：`main` 受保护；功能分支 `feat/<scope>-<slug>` 存活 ≤3 天；发布分支仅 Release Candidate 期 |
| PR | 模板含：变更说明、影响面、测试证据、回滚方式；≥1 评审人；CI 全绿才可合并 |
| 测试义务 | 领域逻辑改动必须带单测；bug 修复必须带回归测试（先复现后修复） |
| 文档 | 架构级变更同步 ADR；同步/AI 协议变更须更新 03/04 文档并在 PR 关联 |
| 密钥 | 禁止入库；客户端 BYOK 密钥只存系统钥匙串/Keystore；服务端密钥走环境注入 |

## 7. 测试策略

### 7.1 测试金字塔与门槛

| 层 | 工具 | 门槛 | 执行时机 |
| --- | --- | --- | --- |
| 领域单测 | `package:test` | 覆盖率 ≥90%（`domain` 包强制） | 每 PR |
| 端上解析单测 | `package:test` + 评估集抽样 | 常用表达 ≥95%（报告 §5.3 验收） | 每 PR + 每夜评估 |
| DB/仓库测试 | Drift 本地测试库 | DAO 全覆盖 | 每 PR |
| 同步测试 | 属性测试 + 混沌套件（见 03 文档 §7） | 全绿为发布阻塞项 | 每 PR 冒烟 + 每夜全量 |
| UI golden | `golden_toolkit`（关键 12 屏，亮/暗 × 中/英） | 无 diff（声明式更新） | 每 PR |
| 集成/E2E | `integration_test` + patrol（捕获条、双端同步、拆解确认流） | 冒烟集 20 例 | 每夜 + 发布前全量 |
| 性能基准 | `tools/seed` 生成 10k 任务库 | 列表滚动 60fps；冷启动 <800ms（mac）；pull 10k 增量 <3s | 每夜 |

### 7.2 同步混沌测试场景清单（Phase 1 S08 建，每夜跑）

1. 双端并发改同字段（时钟正常）→ LWW 收敛一致
2. 双端并发改不同字段 → 两字段均保留
3. 双端并发删/改 → 删除胜（墓碑）
4. 客户端时钟回拨 1 小时 / 快进 1 天 → lamport 兜底正确
5. 断网 7 天（模拟时钟）累积 5k op 后重连 → 最终收敛、顺序正确
6. 拉取中断（游标恢复）→ 不丢不重
7. 10k 任务全量换机（新设备恢复短语登录）→ 数据完整、解密正确
8. 服务端滚动发布（旧/新版本混布 5 分钟）→ 协议前向兼容

## 8. CI/CD

### 8.1 流水线

| 流水线 | 触发 | 步骤 |
| --- | --- | --- |
| `pr-ci` | PR | format check → analyze → 分包单测 → golden UI → 同步冒烟 → 构建冒烟（macOS+iOS 模拟器） |
| `nightly` | 每夜 | 混沌套件全量 → 评估集回归（replay 模式）→ 性能基准 → E2E 冒烟 → 报告到 #eng-daily |
| `eval-live` | 每夜（可选手动） | 评估集真跑（付费 API，预算上限保护）→ 分模型准确率报表 |
| `release-client` | tag `v*` | 构建 → fastlane TestFlight / Play 内测 / Windows 签名包 → Sentry 符号上传 → 变更日志 |
| `release-server` | tag `server-v*` | 构建 Docker → staging 部署 → 冒烟 → 手动批准 → 生产滚动发布 → 备份校验 |

### 8.2 环境

| 环境 | 用途 | 数据 |
| --- | --- | --- |
| dev | 本地 docker compose（Postgres + 服务端） | 种子数据 |
| staging | 云端，私测/公测预发 | 匿名化种子 |
| prod | 云端 | 用户数据（E2EE 密文） |

### 8.3 发布纪律

- 客户端 semver + build number；TestFlight 私测周更（S12 起承诺）。
- 服务端向前兼容一个版本（协议带 `v` 字段）；回滚 = 上一镜像 + 迁移不回退（只前向补偿）。

## 9. 本地开发环境

```bash
mise install                             # 按 mise.toml 锁定 dart 版本
docker compose up -d                     # Postgres（server 服务 S05 接入）
make bootstrap                           # pub workspaces 一次解析全部包
make ci                                  # fmt-check + analyze + test + eval（本地复现 PR-CI）
make eval                                # 本地跑评估集（本地规则适配器，零 API 成本）
make up / make down                      # 本地依赖启停
```

- IDE 共享配置入库（analysis_options、run configurations）。
- 生成代码（Drift/Freezed/JSON）提交入库，保证 CI 与 IDE 一致。
