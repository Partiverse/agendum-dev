## 2. 评估集构建规范（W1–2 建立，长期资产）

- 表达覆盖矩阵：中/英 × 5 类字段（日期、时长、精力、标签、项目提示）× 3 难度（直白/口语/歧义）；每格 ≥8 条，合计 ≥200。
- 对抗样例 ≥15%：错别字、两个日期冲突、无动词短语、方言表达（"下下礼拜三"）。
- 期望值格式：字段级（含"应留空"的负期望）——防止模型过度填充。
- 数据来源边界：访谈与候补名单用户授权的表述，脱敏后入库；禁止爬取他人数据。
- 分层标注：`rule_solvable` / `needs_system_model` / `needs_cloud`——云端命中率高而规则层低时，优先补规则而非调提示词（成本与离线能力双收益）。

## 3. 访谈脚本大纲（45 分钟）

1. 现状与工具史（10min）：用什么管理任务？从哪个工具迁来/为何流失？
2. GTD 实践深度（10min）：收件箱/周回顾/下一步行动三个环节的实际坚持度（引出六大痛点验证）。
3. AI 态度（10min）：给"澄清副驾/拆解师/规划师"三段式演示脚本，记录信任点与恐惧点。
4. 付费意愿（5min）：锚定 $5/$8/$12 三档的直接意愿与买断偏好。
5. 收尾（5min）：候补名单邀请 + 转介绍。

产出模板：每份访谈一页纸（痛点标签、原话引用、付费信号强度 0–2），汇总进 G0 证据包。

## 4. 候补名单与落地页

- 页面三要素：一句话定位（报告 §2.2）、三屏产品概念图（风格样板截图替换）、隐私承诺（"本地优先、AI 可关闭、不卖数据"）。
- 转化目标：G0 前注册 ≥2000（报告标准）；渠道：GTD 中文社群、r/thingsapp、MPU Talk、效率类自媒体首批试水帖。
- 名单运营：双周一封进度信（build-in-public 叙事），降低 G1 私测招募成本。
