## 0. 总评（一句话定性）

**这是一个「内核优秀、外壳失真」的项目：同步与领域内核达到了超出 PoC 阶段的工程水准，但仓库对外声称的三件事——E2EE、AI 原生、可信服务端——目前没有一件是真实成立的；且最严重的缺陷不在「缺功能」，而在「已有代码里的真实正确性 bug」与「零鉴权的服务端把全部明文任务暴露给任何能连上的人」。**

按「如果这是一个要上私测的产品」的标准打分：

| 维度 | 评分 | 一句话 |
| --- | --- | --- |
| 领域内核（状态机/LWW/Lamport/事务） | ★★★★☆ | 单一写路径 + 同事务 oplog，收敛性论证成立，是全仓最强资产 |
| 同步健壮性 | ★★☆☆☆ | 三类真实 bug：毒丸卡死、墓碑丢失、升级丢数据 |
| 安全 | ★☆☆☆☆ | 全端点零鉴权 + pull 全局无租户隔离 + 明文上服务器，当前形态不可上公网 |
| E2EE | ★★☆☆☆（实现 ★★★★☆，落地 ★☆☆☆☆） | 密码学选型与实现质量高，但客户端一根线都没接 |
| AI 原生 | ★☆☆☆☆ | 无任何真实 LLM 调用；「云端回落」与端上是同一份正则 |
| 测试/CI | ★★★☆☆ | 测试文化好，但 CI 与本地范围有缝，PG 裁决路径 CI 零覆盖 |
| 文档可信度 | ★★☆☆☆ | 多项 ADR 未落地，README 数字漂移，「声称/实现」需要一次系统性对账 |
| 产品核心 | ★★☆☆☆ | 「现在，做这件事」是 `tasks.first`；状态机没有 doing |

## 1. P0：可利用漏洞与真实正确性 bug

### 1.1 安全：未认证即可拖走全库明文任务（CWE-306 + CWE-639）

- 服务端全部端点（push/pull/devices/register/AI）零鉴权：`apps/server/lib/src/handler.dart:59-129`、`apps/server/lib/src/ai/routes.dart:27`。
- pull 是**全局**查询、无任何租户/设备过滤：`WHERE seq > @s`（`apps/server/lib/src/store/pg_store.dart:128`、`memory_store.dart:49`）。任何人 `GET /v1/sync/pull` 即可拉走**所有用户的所有 op**。
- 叠加下一节的事实——oplog 当前是**明文**——等价于：服务端在哪儿跑，全库任务明文就在哪儿裸奔。
- 放大器：服务端绑 `anyIPv4`（`apps/server/bin/server.dart:14`）、CORS 全开且允许 authorization 头（`middleware.dart:8-11`）、docker-compose 把 Postgres 5433 端口映射到 `0.0.0.0` 且弱口令明文入库（`docker-compose.yml:8,13`）、PG 连接 `SslMode.require` 不校验证书链（`pg_store.dart:38-40`，应为 verifyFull）。
- deviceId 由客户端自报（`packages/protocol/lib/src/messages.dart:24-27`）：可伪造他人 device_id 注入 op 污染其 LWW 裁决（origin 字典序参与破平，`lww.dart:62-63`）、冒用其 AI 额度。

**结论：当前服务端只能活在 localhost。任何「部署到云上给第二台设备用」的动作都是数据事故。**

### 1.2 E2EE：密码学是好的，但它是一个库，不是一个功能

已实现且质量不低的部分：

- Argon2id m=64MiB/t=3/p=1（`packages/e2ee/lib/src/kdf.dart:11-13`），高于 OWASP 基线；XChaCha20-Poly1305 每次随机 24B nonce（`aead.dart:36-39`），XChaCha 下无复用风险；op 密文 AAD 绑定 `deviceId|lamport|entity|entityId|field`（`op_cipher.dart:25-31`），跨实体搬运密文会被拒；BIP39 12 词 + PBKDF2-HMAC-SHA512 规范实现（`mnemonic.dart:28-34`、`kdf.dart:26-30`）。

但致命落差：

- 客户端建 `SyncEngine` 时**没有传 codec**（`apps/client/lib/views/store.dart:86-93`），回落 `IdentityOpCodec`（`packages/sync/lib/src/sync_engine.dart:84`）——**任务明文上服务器**。E2EE 只存在于 `packages/e2ee` 与它的 24 个测试里。
- 主密钥零持久化：全仓无 flutter_secure_storage/keychain/keyring 依赖；本地 SQLite 也是明文（`packages/db/lib/src/database.dart:53-56`，无 SQLCipher）。
- 服务端无信封（envelope）上传/取回端点（`handler.dart` 仅 push/pull/devices/register）——多设备只剩「人工抄恢复短语」一条路。
- 元数据明文面：field 名、entity、UUIDv7 时序 entity_id、lamport、device_id 全部明文（`pg_store.dart:47-58`）——即使未来 value 加密，每条任务的创建时刻、活动时间线、字段语义、标题长度仍可被服务端观测。这一点应在 ADR-005 里显式声明为「已知取舍」，目前文档未提。

**结论：「E2EE 同步」是当前仓库里落差最大的声称。ADR-005 的「服务端零明文」红线没有达成，而 S07 的提交信息与走查文档会给未来的自己一个错误的安全感。**

### 1.3 同步协议：三个真实正确性 bug + 一个幂等缺口

**B1【高】毒丸 op 永久卡死同步，无逐条隔离。**
`sync_engine.dart:128-137`：任一远端 op 应用抛异常，游标不推进，15s 轮询重拉同一批——一条坏 op 之后的所有同步永久阻塞。而坏 op 是很容易产生的：`task_fields.dart:52-69` 对 value 裸强转（`value as String?`），`op.dart:111-154` 的 fromJson 只验 JSON 形状不验值类型，服务端（`memory_store.dart:28-39`、`pg_store.dart:77-116`）不做任何字段白名单/类型校验即转发。触发场景：任一客户端 push `{field:'due_date', value:{...}}` 一个非预期形状，全网设备同步即死。

**B2【高】远端删除项目后，对端任务永久悬挂。**
docs/03 §承诺「客户端 pull 后做外键修复」（`03-数据模型与同步协议.md:289`），但 `local_sync_store.dart:119-207` 的 applyRemoteOp **直接丢弃 project 实体的 op**（`:123-125`），也没有任何修复逻辑。触发：设备 A 删项目（A 本地任务回收进 inbox）；设备 B 收不到墓碑，任务的 project_id 悬挂、状态不回收，且项目入口消失后这批任务在项目视图不可达——**用户视角是「任务丢了」**。

**B3【中高】未知实体/字段的 op 被跳过，但 pull 游标照推——升级后数据永久缺失。**
`local_sync_store.dart:123-131`：非 task 实体、未知字段一律返回 false（跳过），游标照样越过（`sync_engine.dart:133-134`）；docs §4.3 承诺的 `/v1/sync/snapshot` 补齐通道在服务端根本不存在（`handler.dart` 无此路由）。触发：v1 客户端运行期间流过 project/tag 或新字段 op，客户端升级后 cursor 已越过，数据缺失直到该字段下次被写。

**B4【中】push 无幂等键，ack 丢失即重复；server_seq 回填失真。**
oplog 表无 (device_id, lamport, entity_id, field) 唯一约束（`tables.dart:151-166`），服务端无去重；引擎把整批 localSeq 用单个 `resp.serverSeq` 回填（`sync_engine.dart:114-119`、`local_sync_store.dart:96-106`），服务端逐 op 的 `results[i].accepted` 完全没读。崩溃在「服务端已提交、本地未 markPushed」窗口 → 重推产生重复 op；`oplog.server_seq` 全批等于批尾 seq，列语义失真（目前只有 isNull 判断依赖它，属埋雷）。

**另有 B5【中，产品级】：日期无时区语义。** epochDay 依赖设备当前时区（`domain/dates.dart:11-25`），UTC+8 建的 due_date 飞到 UTC-5「今天」判断漂移一天；DST 跳变日两步猜测不收敛。

### 1.4 editTask 绕过状态机红线（自己定的法，自己先违）

- `editTask` 任意 changes 直写，status 不经 `transition()`，也不联动 completed_at（`task_repository.dart:115-119` vs 正确示范 `:122-132` setTaskStatus）；`_edit`（`:368-406`）不查 `deletedAt`，墓碑行可编辑。
- 客户端还用 `on Error` 基类捕获把 `ArgumentError`（未知字段）误报成「不在允许的流转内」（`task_detail.dart:515`）——与 domain 侧「抛出即 bug，不应静默吞掉」的自述（`status.dart:69`）直接矛盾。
- 同步应用侧 `_materialize` 直写 status（`:152`）同样不设防——「领域红线」实际只在本地 UI 写路径生效。

### 1.5 AI 原生：卖点空心化 + 网关可被一个布尔绕过

- 全仓无任何 LLM HTTP 调用。「云端回落」适配器 `ServerRulesAdapter` 直接 `CaptureParser()`（`ai/adapter.dart:16-22`）——云和端是**同一份正则**。docs/04 六引擎中 2-6（澄清副驾/拆解师/今日规划师/回顾记者/任务库对话）零实现；`packages/ai_client` 自述「占位」。
- 分级强制形同虚设：`byok` 是请求体自报布尔（`ai/routes.dart:54`），置 true 即绕过 L2/L3 数据分级（CWE-603）与月度额度（CWE-770，换个随机 device_id 也行，`quota.dart:46-67` 纯内存账本重启清零）。
- `prompt_version` 未验类型直接 `as String`（客户端发数字即 500），且仅原样回显——docs/04 §7 的提示词版本目录/回滚不存在。

### 1.6 评估集自证循环：「92%」不能外推为「准确率 ≥95%」

- 300 例全部出自同一作者的三个提交（4a37f80 → 634a90e → 6c9ff15），标注者 = 实现者，真实用户语料为 0（README 自认「语料收集还没开始」）。
- README 声称口径要修正：实际是总 276/300（92%），「100%」只出现在 `rule_solvable` 层（242/242）——而该分层标签由同一作者标注且无独立判据：一例规则解不了，标成 `needs_cloud` 即可移出分母，**「rule_solvable 100%」接近同义反复**。
- 标注向实现妥协的实证：zh-140「半小时到一个小时」期望 30、en-095 "1 or 2 hours" 期望 120——把引擎「取第一个/最后一个命中」的实现细节（`parser.dart:144-153`）写成了真值；zh-042 实际产出标题「到 开评审会」仍靠 `title_contains`（178 例宽松断言 vs `title_exact` 121 例）判过。
- harness 机制本身不差（字段级精确匹配 + 负期望防过度填充 + 固定 now 可复现，`harness.dart:177-210`），问题不在机制，在「无独立标注、无真实输入分布」。在 bad-case 回流遥测落地前，这个数字只证明「引擎与评估集内部一致」。

### 2.2 CI 与本地的信任缝隙

- **e2ee 包不在 PR-CI**：`pr-ci.yml` 的循环列了 9 个包，唯独没有 `packages/e2ee`（Makefile MEMBERS 反而包含它）——全仓保护最关键的红线模块，24 个测试 CI 永不执行。
- **PG 裁决路径 CI 零覆盖**：`pg_store_test.dart:30-34` 无 `DATABASE_URL` 即 skip；workflow 无 services 容器。生产用的存储实现从未在 CI 真跑过。
- **Golden 测试已废**：整文件 `@Skip`；字体路径硬编码 macOS（`/Users/nebulaboratories/...`、PingFang.ttc）；11 张基线 PNG 全是 macOS 渲染。渲染回归零防护，且是迁移 Linux 后必须重建的债。
- **db migration 无测试**：`schemaVersion => 3`，v1→v2→v3 两段手写 onUpgrade（`database.dart:31-45`），无任何 upgrade 路径测试、无 drift schema 导出校验。真实用户升级数据库时第一次执行这段代码。
- **nightly 大面积占位**：混沌套件、性能基准是 `echo "placeholder"`；且 nightly 用 dart-only 工具链，db/client/e2ee/demo 都不在内。
- **版本口径三处不一**：mise.toml 注释 3.47.5、CI pin 3.47.4、MIGRATION 写「3.47.x + CI 锁 3.47.4」；mise 全注释，本地版本实际不锁定。

### 2.3 Linux 迁移未闭环（本次调研实测证实）

- MIGRATION §2.4 规定「迁移后第一件事跑 `make ci`，全绿才算迁移成功」——本机 `flutter`/`dart`/`mise` **均未安装**，验收从未执行。
- `apps/client` 无 `linux/` 平台目录（仅 ios/macos），Linux 上无法运行桌面端做走查。
- 全局捕获条（⌥Space）依赖 macOS API，Linux 需要平台抽象，未动工。

### 2.4 计划与现实错位：18 个月 6 人计划 vs 单人 + AI 现实

docs/01-07 是一份 6 人团队、39 个 sprint、18 个月的计划。执行主体实际是单人 + AI 会话。这个错位已经产生症状：W5-W8 的活被提前塞进一周（README 工程进展表），评估集三天从 32 涨到 300 例（同一作者），而真正的硬骨头（E2EE 接线、墓碑传播、migration 测试）原地不动。**产出结构是「容易生成的先涨」——文档、评估集、演示页——而不是「风险最高的先消」。**

## 3. P2：产品核心缺陷

1. **状态机没有 doing**（`domain/status.dart:7-13`：inbox/next/waiting/someday/done/trashed）——「现在，做这件事」的核心交互在状态模型上无处安放。
2. **「现在做这件事」= `tasks.first`**（`today_view.dart:53`）：无任何焦点算法；今日列表仅按 createdAt 倒序（`task_repository.dart:340-356`）。已完成项保留显示删除线是代码注释写明的「Things 行为」设计决定——但 README 走查声称「完成任务→移出今日」，两处口径未对齐，谁是需求没有裁决记录。
3. **捕获条只读预览、不可修正**（`capture_bar.dart:92-144`）：chips 纯展示，回车直接落库；错解析（`@A项目` 误路由、`1/2` 误判日期、zh-042 标题「到 开评审会」这类真实坏例）只能整句重打。
4. **中文口语覆盖缺口**：「月底」「周末」裸词、中文数字时刻（「下午三点」）、「X点一刻」全不支持（`parser.dart:38-71`）；「本/这周三」在周六视角解析成下周三且不提示；非法日期（2月30日）经 `DateTime(y,m,d)` 静默滚动到 3 月（`parser.dart:338`）。
5. **生产入口内置演示种子**：`main.dart:21` `seedIfEmpty: true`，首次启动即把「杭州搬家/补交报销单」写入真实用户库；且 seed 形状为迁就 widget 测试断言而定（`store.dart:337-341` 注释自认）——测试期望反噬生产代码。

## 4. P3：工程细节缺陷（择要）

- MemorySyncStore 与 PgSyncStore 空批量 push 返回分歧（`pg_store.dart:75,118` 返回 0 vs `memory_store.dart:27,41` 返回当前 seq）——客户端游标可能被重置触发全量重拉。
- PG 连接密码不做 percent-decode（`pg_store.dart:28-36`），URL 含特殊字符即认证失败。
- 每次写后 `_reload` 串行 8+ 组全表查询重建缓存（`store.dart:273-308`）——数据量上来后每次拖拽/编辑成本线性上涨；这是放弃 drift watch 流的代价，但没有补偿机制。
- `midpointSortKey('10','100')` 返回 `'100'`，违反「严格介于」契约（`sort_key.dart:42-46`，潜伏）。
- TaskStore 15 处 `await repo.xxx(); await _reload()` 模板重复；字段白名单双 switch 表需人工同步（`task_repository.dart:409-427` vs `task_fields.dart`）。
- AI 月度额度 `aiMonthlyLimit = 30` 等 magic number 无出处；置信度权重 0.40/+0.20/+0.10 无注释（`parser.dart:431-439`）。
- demo 里 `catch (_)` 把协议错误与网络错误统一显示「无法连接服务端」（`demo_app.dart:163`）。
- 全 UI 硬编码中文，无 i18n 层——与 Phase 2「补 Android/Windows」的多端计划冲突。
- CI 的 action 用 tag 引用非 commit SHA pin，无 `permissions:` 白名单（GITHUB_TOKEN 默认写权限）。
