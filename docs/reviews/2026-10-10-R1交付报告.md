## 0. 摘要

R1 把「E2EE 是一个库」变成「E2EE 是默认路径」：服务端退为不可信中继（**同步通道** push/pull/envelope 全量设备签名鉴权 + owner=uid 租户隔离 + 不透明信封端点；AI 网关 `/v1/ai/*` 是已知例外，见 §6-7），客户端首次启动即建立 Vault 身份（BIP39 恢复短语 → 主密钥 → 派生 uid + 数据密钥），oplog value **默认**密文上线——明文模式只剩构建期显式声明一条窄门，且 E2EE 编解码的前向兼容分支仍允许租户内成员推明文 value 原样上线（§6-8，已知放大面）。协议轨先行落盘 wire 契约，服务端 / 客户端 / 集成三个实现轨并行落地后，经一轮安全复核发现 5 处问题，其中两处 medium（nonce 多实例重放、注册不验证 uid 归属）已当批修复并有回归测试钉死，最终 `make ci` 全绿。

## 1. 问题背景（R1 之前的世界）

批评报告 §1.1 实测证实：服务端全部端点**零鉴权**，pull 是**全局**查询（`WHERE seq > @s`，无任何租户过滤），叠加 oplog 明文上服务器——任何能连上服务端的人 `GET /v1/sync/pull` 即可拖走全库所有用户的全部任务明文；deviceId 由客户端自报，可伪造他人身份注入 op 污染裁决、冒用额度。§1.2 同时确认：e2ee 包的密码学实现质量高（Argon2id/PBKDF2 → MK/DK、XChaCha20-Poly1305、BIP39），但**客户端一根线都没接**——线上跑的是 `IdentityOpCodec` 恒等编解码。

R1 的目标因此不是加功能，而是反转信任模型：加密是默认路径，明文是需要构建期显式声明的开发模式；服务端的威胁模型默认「会被攻破/会被运营商看」。

## 2. 改了什么（按轨）

### 2.1 协议轨（packages/protocol）——wire 契约（先行落盘，先于三轨实施）

- `X-Agendum-Auth: v1 <device_id> <nonce_b64> <sig_b64>` 鉴权头与签名原文常量（`agendum/auth:<device_id>:<nonce_b64>`、`agendum/register:<fingerprint>`）：`packages/protocol/lib/src/auth.dart:16-40`。
- 挑战形状 `{nonce, expires_at_ms}` 与解析（`AuthChallenge`，同文件 77-104）。
- 注册请求扩展 R1 字段：`uid`、`uid_proof`（uid 归属证明，可选字段，协议层校验 32 字节 base64）、`pubkey_b64`、`sig_b64`（`src/devices.dart`）；`PushRequest.uid` 必填（`src/messages.dart:38`）。
- 信封 wire 类型 `VaultEnvelope {uid, device_id, envelope_b64}`。
- 以上 wire 契约由协议轨在服务端/客户端/集成三轨开工前落盘（三轨只消费不改动）；协议轨交付时套件 30 用例通过（服务端轨交付时复核的记录），`uid_proof` 字段随后续安全修复（§2.5）加入，现为 32 用例（本报告 §4.1 复跑证实）。

### 2.2 服务端轨（apps/server）

- **挑战端点**：`GET /v1/auth/challenge?device_id=` 匿名可取（nonce 本身无权，鉴权仍要过注册公钥验签）——`handler.dart:81-90`。**限流边界**：服务端无内建限流，匿名灌挑战是可接受的 DoS 面——内存表增速被 TTL 封顶（≈5 分钟窗口 × 挑战速率）；PG 侧除消费时的条件删除外，**签发时惰性清扫过期行**（`nonce_pg.dart:64-65`，`DELETE FROM auth_nonces WHERE expires_at < now()`），故未消费即过期的 nonce 由下一次签发顺带回收、表有界（消费语句 `WHERE expires_at >= now()` 确实不删已过期行，靠的就是这条清扫）；生产部署再加反代限速（ADR-016 §2）。
- **鉴权中间件**：`deviceAuthMiddleware` 包裹 push/pull/envelope 四条路由（`handler.dart:63-65,91,123,248,279`），校验顺序：缺头 → 头畸形 → 未注册 → Ed25519 验签 → **验签通过立即消费 nonce（先于 uid 比对）**（`middleware.dart:50-77`）；任一步不过一律 401。
- **nonce 存储随部署形态**（`NonceStore` 抽象，`auth.dart:32-40`）：单实例内存表 `NonceTable`（32 字节 `Random.secure`、≤5min TTL、签发时惰性清扫）；多实例 PG 共享表 `PgNonceStore`（`store/nonce_pg.dart`）——`auth_nonces` 表 `nonce TEXT PRIMARY KEY` + `expires_at TIMESTAMPTZ`，消费 = `DELETE … WHERE expires_at >= now() RETURNING` 单语句原子完成，TTL 由 DB 时钟校验（免实例间时钟漂移）。`bin/server.dart:11-23` 按 `DATABASE_URL` 装配。
- **注册**：验签（不过 400）+ 指纹自洽 + `pubkey_b64 == public_key` 锚定 + **uid 归属证明准入**（`verifyUidOwnership` 与 e2ee 独立同构实现：uid ≠ hex(HKDF(uid_proof)) → 400 `uid_proof_mismatch`，缺失 → 400 `uid_proof_missing`；明文开发租户 `dev-plain` 豁免）——`handler.dart:174-231`。**豁免边界**：豁免对象是写死的保留 uid `'dev-plain'`（客户端明文模式的固定租户，`packages/e2ee/lib/src/uid.dart:28` 与 `apps/server/lib/src/store/devices.dart:50` 两处同构常量）——该租户本质是开放租户，任何自备密钥并签名者均可注册进入；服务端目前**不支持关闭此豁免**（常量硬编码，无配置项），生产部署如需禁用须先做配置化改造，已登记 §6-11。
- **device→uid 绑定**：首绑为准，重复注册不换绑公钥也不换绑 uid（`store/devices.dart:72-81`）。
- **租户隔离**：Memory/PG 双存储 oplog 加 `owner` 列，`pull` 一律 `WHERE owner = @o`（`pg_store.dart:160`）或内存 owner 过滤（`memory_store.dart:57-58`）；PG 建表含 owner，旧库经 `ALTER TABLE … ADD COLUMN IF NOT EXISTS owner` 兼容（`pg_store.dart:65-83`，旧库 ALTER 路径经服务端轨手工实测：DROP 掉 owner 列后重开重建成功）。
- **信封端点**：`POST/GET /v1/vault/envelope`，每 uid 保留最新一条；Memory + PG `vault_envelopes`（seq 追加式）双实现，服务端不透明存储（`store/envelopes.dart`）。
- 测试：`auth_test`（12 用例）、`devices_test`（11 用例）、`vault_envelope_test`（4 用例）、`server_test`/`pg_store_test` 扩 owner 隔离与 PG 真库用例；测试装置 `harness.dart` 改为 label → 确定性 MK → (uid, proof) 真实派生链，全部服务端测试走真实验证路径。

### 2.3 客户端轨（apps/client + packages/e2ee/sync/db）

- **uid 两跳派生**：`proof = HKDF(MK,'agendum/uid-proof',32B)`、`uid = hex(HKDF(proof,'agendum/uid',16B))`（`packages/e2ee/lib/src/uid.dart:35-46`）——同种子多端必得同一 uid，只知 uid 无法反推 proof。
- **KeyStore 抽象**（`packages/e2ee/lib/src/keystore.dart`）：纯 Dart 接口 + `InMemoryKeyStore`（测试/CI 兜底）；生产实现 `SecureStorageKeyStore`（`apps/client/lib/secure_key_store.dart`，flutter_secure_storage → Keychain/libsecret/DPAPI/Keystore）。持久化的是规范化恢复短语（MK 的等价持有）与设备种子，单一事实来源（`KeyStoreKeys.vaultMnemonic` 注释）。
- **信任身份装配**（`apps/client/lib/identity.dart`）：`IdentityVault.load`（短语创建/恢复 → MK → uid/proof/codec）、`DeviceIdentity.load`（Ed25519 种子持久化）。
- **明文门禁**：`kPlaintextDeclared` 编译期常量 + `resolvePlaintextMode`（显式请求 true 而构建未声明 → `ArgumentError` 启动即炸，`identity.dart:17-34`）；生产入口 `main.dart:19-26` 不传 plaintext，`TaskStore.open` 默认 E2EE + 派生 uid（`views/store.dart:93-99,119-130` 显式传 `vault.codec`）。
- **设备鉴权组装**（`apps/client/lib/device_auth.dart`）：懒注册（首个签名请求前，失败随请求上抛下一轮重试）+ 挑战获取/单条缓存（过期即弃、消费即清）+ Ed25519 签名组装 `X-Agendum-Auth`；注册 body 携带 uid/uid_proof/pubkey_b64/sig_b64。
- **传输钩子**：`RestSyncTransport.authHeaders` 每请求调用（nonce 一次性），push/pull 带 uid（`packages/sync/lib/src/rest_transport.dart:39,58`）；uid 透传链 `TaskStore.open → DriftLocalSyncStore.open(uid:) → 引擎 push/pull`。
- **顺手修复的真 bug**：`packages/e2ee/lib/src/kdf.dart:25-34` 的 PBKDF2 用于 **BIP39 种子派生**（PBKDF2-HMAC-SHA512、2048 轮、512 bit——这组参数是 BIP39 协议规范规定，非本仓自选，`kdf.dart:61-63` 注释即规范原文）。cryptography 默认 `DartPbkdf2` 每 2000 轮注入一次 `Future.delayed(1ms)`「让路」，在 widget 测试 FakeAsync 区真定时器不被泵，导致 `TaskStore.open` 挂死（复现：客户端轨单测 5 分钟无输出）；修复 = `DartPbkdf2(pauseFrequency: 1<<30)` 关闭让路。**本收尾实测支撑**（临时测试跑于 `packages/e2ee`，跑完即删）：默认 vs 关闭暂停各 5 次，输出 64 字节**逐字节一致**（hex 前缀 `27e92bb0…`），耗时 debug 模式中位 ~10.0ms vs ~7.5ms——关闭暂停既不改变 KDF 输出，也没有掩盖可接受的等待（让路机制在此参数下纯属开销与挂死根因）。迭代强度问题：2048 轮的输入是 128 位熵的 12 词短语（BIP39 全生态同参数），不是低熵口令场景；口令→KEK 走的是另一条链 Argon2id（m=64MiB, t=3, p=1，03 文档 §6.1 参数，`kdf.dart:10-14`）。R1 未改任何 KDF 参数。
- 测试：`trust_gate_test`（13 用例）、`device_auth_test`（7 用例）、`uid_keystore_test`（10 用例）、`sync_loop_test` 扩租户隔离用例。

### 2.4 集成轨（apps/client/test/sync_loop_test.dart）

既有两用例（同种子两设备收敛 / 项目墓碑传播）已跑在 R1 服务端上（真实注册 + 挑战签名 + uid 一致性全链路）；新增第三用例**「租户隔离：不同种子的设备（uid 不同）拉不到 A 的 op，线上全程密文」**：异种子设备经 `DeviceAuthService` 真实注册 + 签名（非伪造头）后，收件箱/今日/计划/随时/日志五个任务列表与项目列表全空（测试断言的六组视图数据，`sync_loop_test.dart:145-151`）；原始 HTTP 冒用 A 的 uid pull 得 401；以 A 的 uid 合法拉取断言响应里 `value.t` 全为 `enc` 且响应体不含明文标题「买牛奶」——把安全红线 1/2/3（§3.1–3.3）在一条真实链路里钉死。跨轨接缝（协议形状/头组装/uid 透传/钩子调用时点）逐项读码核对一致，零实现修改。

## 3. 安全红线如何成立（逐条）

以下七条「**安全红线**」是安全复核对蓝图验收红线①②（零明文、不可绕过鉴权）+ R1 契约的细化，**编号独立于 §0 表的验收红线①②③**：安全红线 1/2 支撑验收红线①②，验收红线③的支撑见 §0 表行③。七条均在安全复核中逐条验证、修复后由本报告 §4 的复跑证实仍然全绿。每条给出机制（代码位置）与钉死它的测试名；标注「本收尾复跑」的核对命令为本报告撰写时实际执行（§4.1）。

### 3.1 服务端零明文（红线 1）

- **机制**：E2EE 模式下 op.value 整体封装为 `enc` 密文（`packages/e2ee/lib/src/op_cipher.dart:34-47`，XChaCha20-Poly1305 + AAD 绑定 deviceId/lamport/entity）；服务端落库的只是 op JSON 与不透明 `envelope_b64`（`store/envelopes.dart:68`），全库只持 Ed25519 公钥（`auth.dart:91-111` 仅 verify）与 uid 派生校验（HKDF 单向）。服务端无任何请求体日志——本收尾复跑 `grep -rn "print(\|logger\|log\." apps/server/lib apps/server/bin`，唯一命中 `store/memory_store.dart:35` 的 `_log`（oplog 内存列表名，非日志输出），启动横幅仅 `bin/server.dart:29-33` 一处；`uid_proof` 验后即弃不落库（`DeviceRecord` 只有 deviceId/algorithm/publicKey/fingerprint/uid）。
- **测试**：`engine_encryption_test`『push 落到线上的 value 已加密；pull 端解密还原明文』（第 118 行断言服务端收件箱 `value.type == OpValueTypes.enc`）；`sync_loop_test`『租户隔离：不同种子的设备（uid 不同）拉不到 A 的 op，线上全程密文』（原始 HTTP 断言 `value.t` 全为 `enc`、响应体不含「买牛奶」）；`e2ee_test`『seal:线上 value 为 enc 且不含明文;open 还原』。

### 3.2 无签名/错签/重放一律 401，nonce 不可重放（红线 2）

- **机制**：push/pull/envelope 四条路由全部经 `deviceAuthMiddleware` 包裹（`handler.dart:63-65,91,123,248,279`）；缺头/头畸形/未注册/验签失败/nonce 重放/nonce 过期一律 401（`middleware.dart:50-77`）。nonce 32 字节 `Random.secure`、TTL 5 分钟（`auth.dart:19-23`）；**验签通过立即烧毁、先于 uid 比对**（`middleware.dart:75`），消灭「截获头跨租户试探后原头重放」窗口。多实例部署 nonce 落 PG 共享表，消费为原子 `DELETE … RETURNING`（`nonce_pg.dart:92-102`）。
- **测试**：`auth_test`『无鉴权头 → 401』『头畸形（段数不对/scheme 不对）→ 401』『未注册设备 → 401（即便自带签名）』『签名与注册公钥不符 → 401』『nonce 重放 → 第二次 401』『过期 nonce → 401（TTL 注入时钟验证）』『TTL 边界内（4 分钟）仍可用』『验签通过即烧毁 nonce:改 uid 试探后,原头对正确 uid 也不可用』；`server_test`『未鉴权请求 → 401（无签名/头畸形/未注册设备）』；`pg_store_test`『ADR-016 §1:nonce 共享表多实例单次有效——A 实例消费后 B 实例不可重放』『nonce 过 TTL 即不可消费（DB 时钟校验）』。

### 3.3 租户隔离：uid 取自注册绑定而非请求自报（红线 3）

- **机制**：鉴权通过后写入 `Request.context` 的 `AuthedDevice.uid` **只来自服务端注册绑定记录**（`middleware.dart:80-87`）；push.uid/pull.uid/envelope.uid 与注册 uid 不符一律 401（`handler.dart:116-118,142-144,272-274,291-293`）；pull 一律 `WHERE owner = @o`（`pg_store.dart:160`）或内存 owner 过滤（`memory_store.dart:57-58`）。注册侧由 uid 归属证明保证「能注册进该 uid 的人必持有其 MK」（§3.6）。
- **测试**：`auth_test`『请求 uid 与注册租户不符 → 401』『跨租户 pull 隔离:同服务上 A 租户的 op 对 B 租户设备不可见』；`server_test`『内存存储按 owner 隔离:跨 uid 的 pull 拿不到对方任何 op』『请求 uid 与注册租户不符 → 401;pull 缺 uid → 400』；`pg_store_test`『R1 §5:owner 隔离——跨 uid 的 pull 拿不到对方任何 op』『R1 §5:owner 过滤下的游标推进——别租户的 seq 不产生本租户空页死循环』『R1 §6:vault_envelopes 真库读写——最新一条、跨 uid 隔离』；`vault_envelope_test`『同租户第二台设备可读（多设备恢复路径）,跨租户不可读』；`sync_loop_test`『租户隔离…』（冒用 uid pull 401）。

### 3.4 明文模式门禁：生产默认密文（红线 4）

- **机制**：`IdentityOpCodec` 仅在 `plaintext=true` 分支可达（`identity.dart:73-79`），该值必经 `resolvePlaintextMode`——未用 `-DAGENDUM_PLAINTEXT=true` 构建时编译期常量恒 false，显式请求 true 直接 `ArgumentError` 生产启动即炸（`identity.dart:17-34`）；生产入口 `main.dart:19-26` 不传 plaintext，`TaskStore.open`（`store.dart:93-97`）与唯一生产 SyncEngine 构造（`store.dart:119-130`，显式传 `codec: vault.codec`）默认走 E2eeOpCodec + 派生 uid。**验证边界（如实交代）**：上述真值表与拒绝路径全部由测试覆盖，但测试经 `resolvePlaintextMode(declared:)` 参数注入绕过了编译期常量——「`-D` 定义真能让 `kPlaintextDeclared` 在构建期变 true」这一层**未经真实明文构建验证**（从未以该 define 编译执行过，§4.3/§6-4）。换言之本条的「启动即炸」在未声明构建下已验证；声明构建下的放行路径未实测。
- **测试**：`trust_gate_test` 全套——『本测试构建未声明 AGENDUM_PLAINTEXT(前提自检)』『默认跟随构建期声明:未声明 → 明文关闭』『显式请求 true 而构建未声明 → ArgumentError(启动即炸,不静默降级)』『显式请求 false 恒为关闭』『构建声明 true 时:默认与显式请求 true 均放行(真值表补全)』『默认路径:E2EE + 派生 uid…』等 13 例。
- **如实披露**：`SyncEngine` 构造函数默认值仍是 `IdentityOpCodec`（生产唯一构造点显式传参，现状不违反本条，加固留 R2）；明文构建的验证缺口见上。

### 3.5 密钥材料不落 SQLite、不进日志（红线 5）

- **机制**：短语与设备种子只经 `KeyStore.write` 持久化（`identity.dart:84,110`），生产实现为 flutter_secure_storage 封装（`main.dart:22` + `secure_key_store.dart`）；SQLite 侧 `sync_state` 表只有 deviceId/lamport/lastPullSeq/lastPushAt 四列（`packages/db/lib/src/tables.dart:168-177`）；本收尾复跑 `grep -rni "mnemonic\|masterkey\|datakey" packages/db/lib apps/client/lib`（排除 `*.g.dart`）：`packages/db/lib` **零命中**，client 侧命中全部位于 `identity.dart`/`views/store.dart` 的运行时持有与 KeyStore 读写，无任何 SQLite 落库路径；客户端无密钥材料打印（`device_auth.dart:60` toString 明确不含密钥；sync onTrace 只打实体/字段/lamport 元数据）；`InMemoryKeyStore` 仅测试/CI 兜底（`keystore.dart:32-40` 注释即约定）。
- **测试**：`uid_keystore_test`『短语存取往返:KeyStore 恢复路径重建同一 uid』『两个 InMemoryKeyStore 互不可见(设备边界模拟)』；`trust_gate_test`『重启恢复:同一 KeyStore 重开 → 同短语同 uid』。
- **边界**：真机 Keychain/libsecret 读写未实测（§6-2）。

### 3.6 注册验签 + 首绑不换绑 + uid 归属准入（红线 6）

- **机制**：注册按序校验 algorithm、`pubkey_b64 == public_key`（指纹锚定验签公钥）、`fingerprint == SHA-256(公钥)[:16]` 自洽、uid 归属证明（`uid == hex(HKDF(uid_proof))`，缺失/不符 400）、最后对 `agendum/register:<fingerprint>` 做 Ed25519 验签（`handler.dart:174-231`）；既有 deviceId 重复注册首绑为准，公钥与 uid 均不换绑（`devices.dart:72-81`）——fingerprint = H(pubkey)，故同 fingerprint 不可能换绑不同公钥。
- **测试**：`devices_test`『注册成功:指纹校验通过并回显,绑定 uid;重复注册幂等且不换绑』『指纹与公钥不符 → 400 fingerprint_mismatch』『R1 §3:注册签名错误 → 400 signature_mismatch』『ADR-016 §6:缺 uid_proof → 400 uid_proof_missing（知悉 uid 不够）』『ADR-016 §6:uid 与证明不符 → 400 uid_proof_mismatch（只知 uid 无法入租户）』『ADR-016 §6:归属证明派生链两端同构(独立实现互证)』『ADR-016 §6:明文开发租户 dev-plain 豁免归属证明』『R1 §3:pubkey_b64 与 public_key 不一致 → 400』『algorithm 非 ed25519 → 400』『缺字段（含 R1 新增的 uid/pubkey_b64/sig_b64）→ 400』；`uid_keystore_test`『只知 uid 无法反推 proof:任意 32 字节派生不出该 uid(准入单向性)』。

### 3.7 服务端裁决不读 payload（红线 7）

- **机制**：内存裁决键含 owner（`_headKey(owner, op)`，`memory_store.dart:20-22,36`），只比较 `(op.lamport, op.deviceId)`（`memory_store.dart:37-42`）；PG 裁决是 `(EXCLUDED.lamport, EXCLUDED.origin) >= 现值` 的原子行比较（`pg_store.dart:120-128`）——两实现均不读 op.value/payload 参与裁决（payload 仅在 pull 原样回传）。密文被篡改的后果是客户端 AAD 认证失败，而非影响服务端裁决。
- **测试**：`pg_store_test`『等时钟 (lamport, origin) 字典序破平；幂等重放 accepted』；`engine_encryption_test`『无密钥端拉到密文:解密失败抛 AeadAuthError(同步中断可见)』。

## 5. 已知取舍（汇总）

详见 [ADR-016](../adr/ADR-016-R1-信任层.md)，此处列骨架：

1. **元数据明文面**：E2EE 只覆盖 op.value；uid、device_id、lamport、entity/字段名、seq 时序与密文长度服务端可见（与 ADR-005 设计一致）。
2. **nonce 内存表**：内存 `NonceTable` 单次有效仅单实例成立；「重启即失效」的确切语义是**表清空**——重启前已签发未消费的 nonce 全部提前作废，持旧挑战的客户端重新取挑战即可（拒绝服务面，无安全后果）；**不产生重放窗口**：重启后截获头里的 nonce 查表无果，`consume` 返回 false，同样 401（`auth.dart:74-79`，查无即拒）。多实例部署必须装配 `PgNonceStore` 的原因是「跨实例不共享状态」而非重启。
3. **信封仅 uid 隔离**：租户内任何已注册设备可读可覆盖信封，无每设备 ACL；恶意成员毒化信封属潜伏面（客户端尚未消费信封），遏制归 R2。
4. **PG `entity_lamport` 主键未并 owner**：理论跨租户裁决串扰仅当两租户撞出同一 (entity, entity_id, field) 三元组（entity_id 为随机 UUID，实际不可碰撞）；彻底修复留 dbmate 迁移。
5. **uid 派生链变更属契约破坏**：既有开发库旧租户 uid 全部失效（PoC 库可弃）。
6. **服务端在注册时见到 uid_proof**：不扩大其能力（中继本就能读写全部密文与裁决表），对服务端本体的完整性防御归 R2（op 签名/幂等键）；该边界在 ADR-016 §1 诚实披露。

## 6. 遗留与未覆盖

1. **信封端点客户端未接线**：服务端与 wire 类型已就绪、服务端测试覆盖（同租户第二设备可读/跨租户不可读/404/401/400），但客户端上送/取回未实现。信封内容结构（`packages/e2ee/lib/src/vault.dart:18-29,118-138`）：`KekEnvelope{alg:'argon2id', salt, m/t/p 参数, wrappedMk}`——**口令**经 Argon2id（参数随信封携带）派生 KEK，KEK 以 XChaCha20-Poly1305（AAD `'agendum/envelope-v1'`）包裹 **MK**，零知识（MK/KEK 均不出设备，服务端只存不透明 `envelope_b64`）；对应的恢复闭环 = 新设备凭口令取信封 → 解包 MK → 派生 DK/uid——该链路的客户端上送/取回未实现，故未闭环（当前第二设备恢复走同种子恢复短语，`TaskStore.open(recoveryPhrase:…)`）。属 onboarding 阶段工作。
2. **真机 secure storage 未实测**：全部测试走 `InMemoryKeyStore`；`SecureStorageKeyStore`（flutter_secure_storage → Keychain/libsecret/DPAPI/Keystore）未在真机验证读写。且 `apps/client` 目前只有 ios/macos 平台目录、**无 linux/**——Linux 桌面端尚未 `flutter create --platforms=linux`（蓝图 R3-6 项），本机（Linux）连客户端桌面壳都还起不来，libsecret 路径自然未验证。
3. **golden 基线**：`golden_screens_test.dart` 整文件 `@Skip`（仅 `--update-goldens --no-skip` 显式运行时生成/比对），client 套件的 +1 跳即此；基线未在 Linux 重建（字体渲染差异，蓝图 R3-6 的「golden 测试去 macOS 路径」未做）。
4. **明文构建未实跑**：`-DAGENDUM_PLAINTEXT=true` 构建从未编译执行过；生产路径仍只读编译期常量。
5. **`DeviceRegistrationResponse` 无 `fromJson`**（protocol 轨未提供）：客户端注册仅校验 HTTP 200 + `body.ok == true`（`device_auth.dart:121-129` 注释即此缺口）。
6. **op.device_id 与鉴权设备一致性未强制**：R1 契约仅要求 uid 一致；租户内 op 归属伪造属客户端完整性问题，R2 幂等键 + 快照对账兜底。
7. **AI 网关 `/v1/ai/*` 未纳入鉴权**：`/v1/ai/parse` 仍接收明文文本，是「服务端只碰密文」姿态的已知例外（本分支未改动该面），R5 BYOK 服务端化收口。
8. **已入租户成员的放大面**：明文 value 可穿透 `E2eeOpCodec`（前向兼容分支）、坏密文 `AeadAuthError` 原样上抛可中断受害设备同步、信封可被覆盖毒化——三者均以「已持租户注册设备密钥」为前提，属蓝图 R2-4（服务端入口校验/死信隔离）范围，本次未动。
9. **「第二台设备 10 分钟接入」未做实机人工计时演练**：机制路径（真实注册 + 挑战签名 + 短语恢复收敛）已被集成测试覆盖，但无人拿着一台新设备走过一遍并掐表。
10. **nonce 消费时点的语义选择**：「验签通过立即烧毁、先于 uid 比对」是对契约「验证通过后立即作废」的强解释（防截获头跨租户试探后重放），已用测试锁死该顺序——若后续契约另有裁定需同步改测试。
11. **`dev-plain` 豁免不可配置**：明文开发租户的 uid 归属证明豁免是服务端硬编码常量（`store/devices.dart:50`），生产部署无法关闭——该租户对任何自备密钥者开放（§2.2）。生产化前须将豁免改造成配置项并默认关闭。
12. **设备吊销与密钥轮换缺席**：R1 只有注册、没有吊销——设备密钥泄露后无法将其除名（该设备可持续通过鉴权收发）；恢复短语泄露则等于攻击者可自行派生 uid 与 proof、把设备注册进租户（§2.2 的准入只拦「不持 MK 者」）。且 uid 随短语派生，「换短语」即换租户、历史数据需迁移，不存在原地换钥。在账号体系 v1（服务端租户管理，见附录）与 R2（op 签名/幂等键）落地前，该风险无技术缓解，只有操作纪律：**恢复短语按租户根秘密对待**。此为 R1 信任模型的已知边界（设计现状，非本批引入），登记为后续里程碑的输入。

## §7 实机验收记录（2026-10-10 补记）

### 7.1 验收环境

- 服务端：本机真实部署进程（`dart run apps/server/bin/server.dart`，端口 8080），PG 全套装配（PgSyncStore / PgNonceStore / PgVaultEnvelopeStore），非测试进程。
- 客户端：两台 Android 15 模拟器（独立 AVD = 独立 Android Keystore + 独立 SQLite，等效两台真机），debug APK 经 `--dart-define=AGENDUM_SERVER=http://10.0.2.2:8080` 注入服务端地址。

### 7.3 验收过程中发现并解决的环境问题（沉淀）

1. **Android 构建链**（`apps/client/android/settings.gradle.kts` 已修）：`dl.google.com`/maven central 直连被 TLS 重置 → settings 统一声明仓库（阿里云镜像优先 + `download.flutter.io` 引擎仓库，实测直连可达）+ `PREFER_SETTINGS`；sqlite3 native-assets 需从 github 下载预编译库 → 构建时走本机代理。
2. **Linux 桌面端**（未入库，一条命令可解）：`flutter build linux` 需要 `libsecret-1-dev` 与 `libjsoncpp-dev`（本机仅有运行库）；`linux/` 平台目录本次已入库，装上 dev 包即可构建。
3. **模拟器稳定性**：宿主机内存压力下模拟器偶发被杀、GPU（gfxstream）崩溃 → 第二实例用 `-gpu swiftshader_indirect` 软渲染稳定。
4. **UI 自动化**：MCP ui_tap 坐标映射不可靠，一律改用 `adb shell input tap` 物理坐标。
5. **安全附带确认**：设备注册表当前为服务端内存实现（服务重启丢绑定，客户端懒注册自动恢复）——与 nonce 内存表同类取舍，记入 ADR-016 边界。
