## 1. 验收项与结果

### 1.1 多实例部署形态：跨实例密文收敛 + 异租户隔离 —— ✅ 通过

交付报告 §6-2 指出：集成测试的「真实服务端」是进程内 shelf handler，从未跑过**独立部署进程**。本次部署补上：

- 部署形态：Postgres 16 容器（净库重建）+ **两个独立服务端 OS 进程**（`dart run apps/server/bin/server.dart`，PORT=8091/8092，均以 `DATABASE_URL` 走 PG 模式）；两实例 `/v1/health` 均报 `"store":"PgSyncStore"`。
- 设备 A（实例①）捕获任务并 push；设备 B（实例②，同 BIP39 恢复短语）经真实 TCP 注册（挑战-签名）、拉取密文并解密——两端 uid 一致，任务收敛可见。
- 异种子设备（不同 uid）经实例②全量同步后，收件箱等视图为空——跨租户隔离在双实例 + PG 形态下成立（对应安全红线 1/3 的部署级验证）。
- 结果：`flutter test test/acceptance_deploy_test.dart`（`AGENDUM_ACCEPTANCE_BASES` 门控）**2 例全过**。

### 1.2 持久性：服务端重启后数据可恢复 —— ✅ 通过

- kill 实例② → 重新启动（同 PG）→ 全新设备（同短语）经实例②同步，`pull 2 ops`，阶段一的任务照常恢复。
- 证明 oplog、设备注册表在 PG 真实持久，鉴权与同步链路不依赖进程内存态。对应交付报告「机制交付、实机验收未完」的部署侧闭环。

### 1.3 明文门禁的声明构建 —— ✅ 通过

交付报告 §3.4 如实声明过的未实测层：「`-DAGENDUM_PLAINTEXT=true` 真能让编译期常量变 true」从未被真实构建验证。本次：

- 以 `flutter test --dart-define=AGENDUM_PLAINTEXT=true` 真实构建执行临时测试：`kPlaintextDeclared == true`、`resolvePlaintextMode() == true`、`resolvePlaintextMode(requested: true) == true`——声明放行路径成立。
- 未声明构建的 `trust_gate_test` 复跑 **14 例全绿**（默认关闭、显式请求即炸的红线不受影响）。临时测试跑完即删，不入库。

### 1.4 验收脚手架入库 —— ✅

`apps/client/test/acceptance_deploy_test.dart`：环境门控（未提供 `AGENDUM_ACCEPTANCE_BASES` 时 `markTestSkipped`，整体 skip、退出码 0），不干扰常规 CI；两阶段分别验收敛与重启持久性，供日后部署验收复用。

## 2. 环境与命令

```bash
# 部署
docker compose down -v && docker compose up -d          # 净库 PG
PORT=8091 DATABASE_URL='postgres://agendum:agendum_dev_only@localhost:5433/agendum_dev' \
  dart run apps/server/bin/server.dart                   # 实例①
PORT=8092 DATABASE_URL=… dart run apps/server/bin/server.dart  # 实例②

# 阶段一(收敛+隔离)
AGENDUM_ACCEPTANCE_BASES='http://localhost:8091,http://localhost:8092' \
  flutter test test/acceptance_deploy_test.dart          # +2: All tests passed

# 阶段二(kill 实例②重启后)
AGENDUM_ACCEPTANCE_BASES=… AGENDUM_ACCEPTANCE_PHASE=2 \
  AGENDUM_ACCEPTANCE_PHRASE='<阶段一打印的短语>' \
  flutter test test/acceptance_deploy_test.dart          # +2: All tests passed(pull 2 ops)

# 明文声明构建(临时测试,跑完即删)
flutter test test/_tmp_define_acceptance_test.dart --dart-define=AGENDUM_PLAINTEXT=true
```

验收用的恢复短语为一次性 fixture（仅存在于测试进程内存与 InMemoryKeyStore），验后即弃，非任何真实租户密钥。

## 3. 结论

R1 验收**在本机可验范围内全部通过**：部署形态（独立进程、PG、双实例）、持久性、声明构建三层此前未验证的缺口补齐；`make ci` 于验收改动后复跑全绿。安全红线③的状态从「机制交付、实机验收未完」升级为「**部署形态已验，真机链路待测**」。

## 4. 仍未覆盖（需真机/真实部署环境）

- `flutter_secure_storage` 走真实 Keychain/Keystore/libsecret 的密钥持久化（本机无 keyring，测试链路为 InMemoryKeyStore）。
- 两台真实物理设备经真实网络（域名 + TLS）接入；本地验收为 loopback 明文 HTTP——生产部署必须置于 TLS 反代之后（ADR-016 §2）。
- `dev-plain` 豁免租户的生产禁用配置化（交付报告 §6-11，R2 待办）。
