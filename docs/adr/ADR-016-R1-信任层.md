# ADR-016 · R1 信任层：设备鉴权、uid 租户隔离、信封中继与明文门禁

- 状态：已采纳（2026-10-10，R1 信任革命实施时确定）
- 关联：[革命性改进蓝图](../reviews/2026-10-09-革命性改进蓝图.md) §2、[03-数据模型与同步协议](../03-数据模型与同步协议.md) §4.4/§6.1、ADR-005（E2EE，见 02 文档 ADR 表）、[R1 交付报告](../reviews/2026-10-10-R1交付报告.md)

## 背景

R1 把服务端改造为不可信中继：push/pull/envelope 一律要求设备签名
（`X-Agendum-Auth: v1 <device_id> <nonce_b64> <sig_b64>`），oplog 按
owner=uid 隔离，新增不透明信封端点；客户端把 E2EE 从库接线成默认路径。
密码学实现（e2ee 包）、codec 插座、设备注册端点在 R1 前均已就绪（批评
报告 §6.3），缺的只是接线与密钥管理闭环。契约（R1 wire 契约 §1–6）之外
有六个实现层决策需要记录。

## 决策

### 1. uid 两跳派生 + 注册准入（MK 持有证明）

uid 是服务端的租户路由键（owner=uid），在每个 push/pull 里明文出现，
不能当秘密。若注册只验设备密钥自洽，任何人生成密钥对即可把设备注册进
**任意 uid 字符串**名下，拿到该租户的 pull（密文全量）、信封读写与
push 权——而服务端是威胁模型声明的不信方，从 DB 读到 uid 即可利用。
故 uid 改为两跳派生（e2ee `uid.dart`）：

```text
proof = HKDF(MK, info: 'agendum/uid-proof', 32 字节)   ← wire uid_proof
uid   = hex(HKDF(proof, info: 'agendum/uid', 16 字节))
```

注册请求携带 `uid_proof`，服务端 `verifyUidOwnership`（与 e2ee 独立同构
实现，互证）重算 HKDF 与声明的 uid 比对：缺失 400 `uid_proof_missing`，
不符 400 `uid_proof_mismatch`。持 MK 者必能出示 proof（多端同短语同
推导）；只知 uid 无法反推 proof（HKDF 单向），「知悉 uid 即可入租户」
的缺口由此关闭。

**取舍与边界**：
- uid 派生链变更属契约破坏——既有开发库的旧租户 uid 全部失效（本地/
  PG PoC 库可弃，同 §4 先例）。
- proof 只在注册请求出现，服务端验后即弃、不落库；它不泄露 MK 也推不
  出 DK（HKDF 单向 + info 域分离）。诚实披露：**服务端自己在注册时看
  到 proof**，故可注册任意设备——但服务端作为中继本就能读写全部密文
  与裁决表，这不扩大其能力；准入防的是「DB 读取者/知晓 uid 的第三方」，
  对服务端本体的完整性防御属 R2（op 签名/幂等键）。
- 明文开发租户 `dev-plain` 无 Vault，豁免准入（共用开发租户，本来就是
  开放租户）。
- 设备私钥仍是每设备独立生成：准入证明只证明「注册者持有租户 MK」，
  设备密钥轮换不受 MK 约束。

### 2. 鉴权：挑战端点 + 单次 nonce + Ed25519 验签

`GET /v1/auth/challenge` 匿名可取（nonce 本身无权，鉴权时仍要过注册
公钥验签）：32 字节 `Random.secure` nonce、≤5 分钟 TTL。每个受保护
请求带 `X-Agendum-Auth: v1 <device_id> <nonce_b64> <sig_b64>`，服务端
按注册公钥验签 `agendum/auth:<device_id>:<nonce_b64>`，缺头/头畸形/
未注册/验签失败/重放/过期一律 401（middleware.dart）。

**消费时点**：验签通过立即烧毁 nonce，**先于 uid 比对**。截获的合法
鉴权头若被拿去跨租户试探（uid 不符 → 401），nonce 已被消费——之后用
原头对正确 uid 重放同样 401；若反过来（uid 不符不烧 nonce），攻击者可
反复试探、最终以正确 uid 重放成功，单次性名存实亡。

**nonce 存储随部署形态**（`NonceStore` 抽象，二选一）：
- **内存 `NonceTable`**：单实例/开发部署。重启即失效——客户端重新取
  挑战即可，nonce 丢失无害。**单次有效只在单进程成立**。
- **PG `PgNonceStore`**（store/nonce_pg.dart）：DATABASE_URL 部署明确
  是多实例设计，负载均衡下「实例 A 消费过的 nonce 可在实例 B 重放」
  会让单次有效失效——nonce 落共享表 `auth_nonces`
  （`nonce TEXT PRIMARY KEY` 唯一约束 + `expires_at TIMESTAMPTZ` TTL），
  消费 = `DELETE … WHERE expires_at >= now() RETURNING` 一条语句原子
  完成，任意实例并发消费同一 nonce 至多一次成功；TTL 由 **DB 时钟**
  计算与校验，免实例间时钟漂移。

匿名可取挑战是可接受的 DoS 面：内存增速被 TTL 上限封顶（≈5 分钟窗口
× 挑战速率），PG 表同理由惰性清扫封顶；生产部署加反代限速即可。

### 3. device→uid 首绑为准，重复注册不换绑公钥也不换绑 uid

既有「同 fingerprint 重复注册不换绑公钥」语义保持；R1 起同样不换绑
uid——防注册通道把已有设备改挂到别的租户。设备换主（恢复短语变更导致
uid 变化）应生成新 deviceId 重新注册（产品决策，换绑流程留后续）。

### 4. 租户隔离：oplog owner=uid，PG 加列不拆主键

`sync_ops` 与 `entity_lamport` 增 `owner TEXT NOT NULL` 列，建表语句
含 owner，既有库经 `ALTER TABLE ... ADD COLUMN IF NOT EXISTS ... DEFAULT ''`
兼容；`pull` 一律 `WHERE owner = @o`，跨 uid 拿不到对方任何 op。
**取舍**：`entity_lamport` 主键保持 `(entity, entity_id, field)` 不变
（拆键需重建约束，超出「ADD COLUMN 兼容」的契约；PoC 库可弃）。理论上
的跨租户裁决串扰仅当两租户出现同一 `(entity, entity_id, field)` 三元组
——entity_id 为客户端随机 UUID，实际不可碰撞；彻底修复（主键并入
owner，dbmate 迁移）留给账号体系 v1。内存实现无此残留：裁决键含
owner，完全隔离。

### 5. 信封端点：每 uid 保留最新一条，服务端不透明

`POST/GET /v1/vault/envelope`：上传/取回 KEK 加密的 MK 信封（第二台
设备凭恢复短语解锁后经此接密钥，服务于「无短语仅 DK 包裹」的设备恢复
路径）。PG `vault_envelopes`（seq BIGSERIAL 主键 + (uid, seq) 索引）
追加写入，GET 取 `ORDER BY seq DESC LIMIT 1`；服务端不透明存储，不
解析、不校验内部格式，仅验 base64 可解且非空（协议层已保证）。旧信封
行留存作审计痕迹，后续随 GC 策略清理。

### 6. 明文模式门禁：构建期声明，缺省即密文

明文开发模式（`IdentityOpCodec` 恒等编解码）只允许在构建期声明
`--dart-define=AGENDUM_PLAINTEXT=true` 时启用（`kPlaintextDeclared`
编译期常量，运行时不可翻转）。显式请求明文而构建未声明 →
`ArgumentError`，生产误入在启动即炸而非静默降级（`resolvePlaintextMode`，
truth 表有测试）。生产入口（main.dart）不传 plaintext，`TaskStore.open`
默认走 E2eeOpCodec + 派生 uid；明文租户固定 uid `dev-plain`。

**边界（如实披露）**：`SyncEngine` 构造函数的 codec 参数默认值仍是
`IdentityOpCodec`，当前生产唯一构造点显式传 `vault.codec` 故不违反
本决策；「默认值改必填/断言拒绝」的加固留 R2。

## 已知取舍

- **元数据明文面**：E2EE 只覆盖 op.value——uid、device_id、lamport、
  entity/entity_id/field 字段名、seq 时序与密文长度服务端全部可见
  （与 ADR-005 的设计一致）；entity_id 如需隐藏，规划 v2 换随机 UUID
  （蓝图 §2-7 已列兼容成本）。
- **nonce 内存表**：内存 `NonceTable` 的单次有效仅单实例成立（§2），
  内存部署（不设 DATABASE_URL）重启即失效；多实例部署必须装配
  PgNonceStore，否则红线「不可重放」失效。
- **信封仅 uid 隔离**：信封只按 uid 隔离，租户内任何已注册设备都可
  读取并覆盖——无每设备 ACL；已入租户的恶意成员可把信封覆盖为自己的
  KEK 包裹（当前客户端尚未消费信封，毒化属潜伏面；遏制与租户内成员
  信任模型归 R2）。

## 后果与约束

- 服务端对 uid 不做格式假设（不透明非空字符串）；无 DATABASE_URL 的
  内存部署仅限开发/演示。
- AI 网关路由（/v1/ai/*）本期未纳入鉴权，为 R5「BYOK 服务端化」预留
  （蓝图 §6.2）；push/pull/envelope 已全部 401 把关。
- op.device_id 与鉴权设备的一致性未强制（契约只要求 uid 一致）；租户
  内 op 归属伪造属客户端完整性问题，由 R2 幂等键与快照对账兜底。
- 注册准入（§1）关闭「无 MK 者入租户」的入口；**已入租户的成员**推
  明文 value / 坏密文的放大面不变——那需要「已注册设备密钥泄露」为
  前提，其遏制同样属 R2（死信隔离/入口校验）。
