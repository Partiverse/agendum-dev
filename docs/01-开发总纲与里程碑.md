# 01 · 开发总纲与里程碑

> 上游依据：可行性报告 §7（可行性）、§8（路线图）、§10（KPI）。本文档将其转化为可执行的迭代节奏、闸门机制、团队分工与风险管理。

---

## 1. 目的与承接关系

本计划回答一个问题：**6–8 人团队如何用 18 个月把可行性报告中的四阶段路线图逐项落地**。产品定义、市场分析、定价策略以报告为准，本文不做重复；本文新增内容是报告未展开的工程侧决策：

- 迭代节奏与日历锚点（§2）
- 每阶段的范围基线、明确不做清单、闸门评审流程（§3）
- 团队编制、扩编时点与职责矩阵（§4）
- 风险的**工程触发器**——报告的风险登记册给出"对策"，本文给出"何时触发对策"的量化条件（§6）
- KPI 的埋点落地责任（§7）

本计划补充的技术决策（后端语言、加密套件、计费方案等）以 ADR 形式记录在 [02-工程架构与规范](02-工程架构与规范.md) §3。

## 2. 迭代节奏与全局里程碑

### 2.1 节奏

- **双周 sprint**（S01–S39），全程 18 个月 ≈ 78 周；S38–S39 为 1.0 发布缓冲与发布后修复。
- 每 sprint：周一规划会（1h）→ 每日站会（15min，异步文字亦可）→ 周五 demo（30min，全员可见进展）→ sprint 末回顾（45min）。
- **月度闸门评审**：每月末对照当月里程碑与阶段退出标准出红绿灯报告；连续两个月红灯触发 §6 风险触发器。
- 分支策略：trunk-based，短生命周期分支 + PR 评审（详见 02 文档 §6）。

### 2.2 日历锚点（假设 kickoff 2026-10-05，可整体平移）

## 3. 阶段定义与闸门

> 范围基线来自报告 §8；"明确不做"是纪律条款，变更须产品负责人书面批准并同步风险登记册。

### 3.1 Phase 0（M1–2）：花小钱买确定性

| 项 | 内容 |
| --- | --- |
| 目标 | 验证：①AI 澄清/拆解质量达"可信赖副驾"标准；②目标人群付费意愿 |
| 交付 | 用户访谈 20 人、捕获解析+项目拆解 CLI 原型、评估集 v1（≥200 条）、同步 PoC（双端并发收敛）、Flutter 风格样板、落地页+候补名单、商标检索启动 |
| **退出标准（G0）** | 解析准确率 ≥90%；候补名单 ≥2000；访谈中 ≥60% 愿为定位付费 ≥$5/月 |
| 不达标动作 | 回炉定位或收缩 AI 范围至"捕获+回顾"两个已验证场景（报告 §7.7 风险 2 的预案），**不进入 Phase 1** |

### 3.2 Phase 1（M3–7）："GTD 骨架 + 智能捕获"

| 项 | 内容 |
| --- | --- |
| 功能范围 | 收件箱/今日/计划/随时/项目（嵌套+next action）/标签（互斥组）/截止与暂缓日期/重复规则/日志簿；全局捕获条+自然语言解析（端上优先）；基础搜索与键盘流；macOS+iOS；E2E 加密多端同步（TestFlight 私测）；BYOK 云端 AI：项目拆解师 v1 |
| 明确不做 | 日历集成、今日规划师、回顾记者、澄清副驾、任务库对话、协作、Android/Windows、计费、分享面板（Phase 3） |
| 团队 | 6 人全员到位（S05 前） |
| **退出标准（G1）** | 200 名种子用户；次周留存 ≥45%、月留存 ≥25%；崩溃率 <0.1%；同步零丢失（混沌套件全绿）；AI 拆解"可直接使用"比例 ≥50% |

### 3.3 Phase 2（M8–12）：把"副驾"变成"员工"

| 项 | 内容 |
| --- | --- |
| 功能范围 | 澄清副驾（收件箱批处理）；今日规划师 v1（Google Calendar/CalDAV/EventKit 双向）；回顾记者（周报+追问）；任务库对话 v1；时间追踪+番茄钟（estimate/actual 闭环）；Android、Windows 公测；订阅计费（免费档+Pro）；AI 额度与 BYOK 体系 |
| 市场动作 | 公测发布、效率社区/自媒体首轮投放、公开路线图运营（G1 通过后启动招聘增长 1 人） |
| **退出标准（G2）** | 付费转化率 ≥4%；AI 功能周采纳用户占比 ≥50%；周回顾打开率 ≥30%；NPS ≥40 |

### 3.4 Phase 3（M13–18）：成为"个人 AI 时代的任务底座"

| 项 | 内容 |
| --- | --- |
| 功能范围 | **MCP Server + 公开 API**（置于首位）；邮件转发捕获；分享面板全平台；今日规划师 v2（实际用时反哺、节奏学习）；智能透视编辑器；Web 端（只读+轻编辑）；本地化（中/英/日）；1.0 正式发布+限时创始买断档 |
| 评估项 | 只读分享链接（谨慎）；插件系统立项调研（仅调研，不承诺） |
| **退出标准** | 1.0 正式发布；注册 ≥15 万、付费 ≥6000；MCP/API 第三方集成案例 ≥10；收入覆盖 ≥60% 运营成本 |

## 6. 风险登记与工程触发器

> 报告 §7.7 风险登记册给出"对策"；本文补充**触发条件→触发动作**，使风险管理可执行。评审频率：月度闸门评审必查。

| # | 风险 | 等级 | 触发条件（量化） | 触发动作 | 责任 |
| --- | --- | --- | --- | --- | --- |
| 1 | 自研同步数据丢失 | 低/极高 | 混沌套件任一收敛失败；或私测期间出现 1 例用户数据丢失报告 | 冻结同步相关发布；72h 内根因分析；若 S08 末混沌套件仍不全绿 → 启动 PowerSync 备选方案切换评估（预留 4 周切换预算） | B1 |
| 2 | AI 质量不达可信赖 | 高 | 评估集周回归连续 2 周低于门槛；或私测采纳率 <40% | 收缩 AI 范围至"捕获+回顾"；加大端上规则占比；回到 Phase 0 预案 | A1/P0 |
| 3 | 付费转化 <4% | 中 | G2 前测转化 <3% | 定价 A/B（$8→$6）；强化免费档转介绍；买断档提前 | P0 |
| 4 | 进度蔓延 | 中 | 任一 sprint 交付率 <70% 连续 2 次；或 Phase 里程碑月度红灯 ×2 | 范围裁剪会：按"明确不做"清单反向砍范围；冻结新需求至闸门 | P0 |
| 5 | Flutter 平台质感不达标 | 中 | 走查红线清单连续 2 次未过 | 追加 15–20% 打磨工时（已预留）；必要时关键页面（捕获条/今日视图）原生实现 | C2/D1 |
| 6 | LLM 成本超预期 | 低/中 | 单付费用户月均云端成本 >$2 连续 2 月 | 档位降级路由（拆解降为轻量模型）；额度收紧；BYOK 引导 | A1 |
| 7 | 头部竞品补齐 AI×GTD | 高 | 任一头部产品发布 GTD 深度 AI 功能 | 加速 Phase 2 差异化功能（回顾/对话）；营销转向"隐私+方法论"叙事 | P0 |
| 8 | Apple 平台政策变化 | 低/中 | 审核指南变更影响支付/后台任务 | 政策评估 1 周内出结论；多平台对冲（Android/Windows 提前） | B1/P0 |

## 7. KPI 与埋点责任

> 目标值体系见报告 §10。本节定义**支撑 KPI 的最小事件字典**——埋点缺失等于 KPI 失明。

### 7.1 事件字典（Phase 1 起生效，隐私白名单制，见 02 文档 §3 ADR-009）

| 事件 | 关键属性 | 支撑指标 |
| --- | --- | --- |
| capture_used | source(全局条/应用内), parsed_ok | 激活（3 次 AI 捕获）、公理 1 |
| ai_suggestion_shown / accepted / rejected | engine(拆解/澄清/规划), reason_shown | 建议采纳率 ≥70%、AI 周采纳 ≥50% |
| plan_generated / plan_block_accepted | accepted_count | 规划采纳 ≥3 天/周 |
| review_opened / review_followup | period | 回顾打开率 ≥30% |
| task_completed | status_before, project_depth | 北极星、留存 |
| inbox_processed | count, ai_assisted | 收件箱 7 日清空率 ≥60% |
| sync_error | code, severity | 同步零丢失 |
| subscription_converted | plan, trial_days | 转化 ≥4% |

### 7.2 责任

- A1 定义事件 schema 与采集版本；B1 保证上报管道（离线缓存补发）；P0 出看板（月度）。
- 禁令：不采集笔记正文、不采集任务标题明文（遥测仅含结构化计数与枚举），与隐私公理一致。
